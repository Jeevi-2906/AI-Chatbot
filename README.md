# LLM API Integration Chatbot (AI-1)

An academic, full-stack conversational AI application integrating Google's Gemini Large Language Model API. Built with Flask, vanilla frontend technologies, multi-turn session memory, and Last-N context window management.

---

## 1. Project Overview

This project satisfies all requirements for the **AI-1 Academic Assignment (100 Points)**. It is **not** a rule-based or hardcoded decision-tree bot; every assistant response is dynamically generated by Google's official Gemini Large Language Model API (`google-genai` SDK).

The application is specifically engineered as a **Friendly Educational AI Assistant**, designed to explain programming and computer science concepts to beginners using simple language, real-world analogies, and structured formatting.

---

## 2. Key Features

- **Genuine Multi-Turn Dialog Memory**: Maintains separate, in-memory conversation histories indexed by unique session UUIDs. The assistant actively recalls facts and context introduced earlier in the conversation.
- **Context Window Management (Last-N-Message Truncation)**: Prevents context overflow and minimizes token consumption by dynamically slicing the most recent $N$ messages (configurable via `MAX_HISTORY_MESSAGES`) while retaining complete user-assistant turn pairs.
- **Educational System Persona**: Guided by a dedicated system instruction that enforces clear explanations, illustrative examples, structured formatting, and contextual continuity.
- **Production-Grade Error Handling**: Gracefully intercepts invalid inputs (400), authentication failures (401), rate limits (429), and transient API spikes (503), rolling back incomplete turns so conversation state is never corrupted.
- **Strict Credential Security**: API keys are isolated exclusively in the backend using `python-dotenv`. Credentials and internal stack traces are never exposed to the client or committed to Git.
- **Modern Responsive Frontend**: Built with pure HTML5, CSS3, and Vanilla JavaScript using the Fetch API. Features include auto-scrolling, an auto-resizing textarea, Enter-to-send (Shift+Enter for newline), an animated typing indicator, and a session reset ("New Chat") button.

## 6. Installation and Setup

### Prerequisites
- Python 3.10 or higher
- Git installed on your system
- A free Google Gemini API key from [Google AI Studio](https://aistudio.google.com/)

### Step 1: Clone the Repository
```bash
git clone <your-repository-url>
cd LLM-API_Integration
```

### Step 2: Create and Activate Virtual Environment
**On Windows (PowerShell):**
```powershell
python -m venv venv
.\venv\Scripts\activate
```

**On macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

### Step 3: Install Dependencies
```bash
pip install -r requirements.txt
```

### Step 4: Configure Environment Variables
Copy the example environment file:
```bash
cp .env.example .env
```
*(On Windows PowerShell, use `Copy-Item .env.example .env`)*

Open `.env` in any text editor and insert your Gemini API key:
```env
# Google Gemini API Key (Get from https://aistudio.google.com/)
GEMINI_API_KEY=your_actual_gemini_api_key_here

# Configurable Gemini Model (e.g., gemini-3.5-flash)
GEMINI_MODEL=gemini-3.5-flash

# Context Window Management (Number of recent messages to retain in API request)
MAX_HISTORY_MESSAGES=6

# Flask Configuration
FLASK_PORT=5000
FLASK_DEBUG=True
```

## 8. API Specification

### `POST /chat`
Submits a user message and returns the model response within the specified conversation session.

- **Headers**: `Content-Type: application/json`
- **Request Body**:
  ```json
  {
    "message": "My name is Jeevika.",
    "conversation_id": "session-12345"
  }
  ```
- **Response (`200 OK`)**:
  ```json
  {
    "response": "Hello Jeevika! It's great to meet you. What would you like to learn today?",
    "conversation_id": "session-12345"
  }
  ```
- **Validation Errors (`400 Bad Request`)**:
  ```json
  { "error": "Validation error: 'message' is required and cannot be empty." }
  ```

### `POST /chat/reset`
Clears in-memory conversation history for the given session.

- **Request Body**:
  ```json
  { "conversation_id": "session-12345" }
  ```
- **Response (`200 OK`)**:
  ```json
  {
    "status": "cleared",
    "conversation_id": "session-12345",
    "message": "Conversation history has been reset successfully."
  }
  ```

### `GET /health`
Returns the operational health and active model configuration of the backend server.

## 9. Context Window Management: Last-N Truncation

### Why Context Truncation is Critical
1. **Token Cost & Rate Limits**: Unlimited conversation history causes token counts to balloon linearly with each turn, increasing latency and hitting API quotas prematurely.
2. **Context Window Overflow**: LLMs have hard token input limits. Truncation guarantees the prompt size remains bounded.

### Truncation Algorithm
1. The full transcript is retained in Python memory (`conversations[conversation_id]`) for auditing and user interface persistence.
2. When dispatching a request to the Gemini API, only the most recent $N$ messages (defined by `MAX_HISTORY_MESSAGES`) are extracted.
3. **Turn-Pair Integrity**: If slicing `[-N:]` begins with an orphaned `assistant` message, the leading message is automatically pruned so the dialog sent to Gemini always begins cleanly with a `user` prompt.
4. **Guaranteed Recency**: The latest user message is always preserved at the tail of the request payload.

## 12. Limitations & Future Scope

- **In-Memory Volatility**: Conversation history is currently stored in Python memory dictionaries and will clear upon server restart. *Future scope*: Add SQLite or PostgreSQL persistence.
- **RAG Integration**: Long-term memory could be augmented with vector embeddings (e.g., ChromaDB) for semantic retrieval over past conversations.
- **User Authentication**: Currently tracks sessions via client UUIDs; could be expanded to multi-user account authentication (e.g., Flask-Login).
